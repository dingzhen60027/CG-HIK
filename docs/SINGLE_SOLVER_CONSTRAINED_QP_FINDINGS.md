# 真实受限 QP：活动集参照与轨迹机制

## 结论

**不支持当前 NumPy 专用内核相对成熟活动集实现的效率优势。** 官方 qpOASES 在本轮所有矩阵输入上通过共同精度检查，常规、单边界、多边界和换集组均更快。旧结果中相对缓存 OSQP 的优势仍是特定后端/接口的事实，不能升级为“专用活动集更先进”。

有界协同求步的局部作用得到更直接的证据：六条指定轨迹在最早方向差异处具有完全相同的实际输入；约束活动、其余关节重分配和非线性残差下降均可逐项检查。但 UR5e 失利例也获得更好的局部下降，随后仍失败，因而这些证据支持**正确处理当前边界的数值作用及有限工程收益**，不支持普遍续接优势、新活动集原理或居中项创新。

## 数据与执行边界

基线 `be75d28ceadd519401c699cb9d5f125f3c5bc4fe`。主 GN、κ、阻尼、回溯、停止条件、verifier、七设置原记录和论文均不变。本轮没有新目标、没有新整轨迹性能评估。

- 原自然开发库独立保留：Panda 971 个、UR5e 1000 个 QP，来源各 8 个 UID；其中强活动约束 QP 仍为 0/3。
- 补充采集逐条复放原 GN κ=1 第 0 遍记录中的**准确当前输入**，共 320 个 UID、48,000 帧。每帧使用该帧原有 `previous_q`，不让诊断运行的差异继续反馈；因此这是历史输入复放，不是新闭环评估。每条轨迹只复放一遍。
- 捕获原函数内部 H/g/lo/hi、线性化 q、阻尼、步长、残差及真实返回方向；主时钟、20 ms 软上限和数值逻辑未改。分类和额外 FK 检查在求解调用外进行。Panda 仅 1 帧返回 q 差异超过 1e-8，接受状态无变化；UR5e 无此差异。具体为 trajectory_144/f60：原 stationary，复放 deadline，诊断耗时 71.50 ms，q 最大差 0.01623 rad，双方均拒绝。该差异及不完整的内部更新覆盖原样记录，不能将复放计时当成原在线计时。
- 保存全部 52,922 个矩阵及其时序元数据。针对受限/多更新 QP，Panda 候选 5429 个，按 UID 均衡固定抽取 2000 个（22 UID）；UR5e 1903 个全部保留（16 UID）。恢复原时间顺序后计时，未按速度或后续结果挑选。定向库包含最终无活动边界、但内部有加/释放操作的 4/5 个 QP。
- 强活动状态必须同时满足边界距离 ≤1e-8、正确乘子符号及绝对幅度 >1e-9，并且完整 KKT 检查合格；弱接触单列。本轮未观察到弱接触或原活动集不合格解。内部换集用 Python trace 观察**未修改的原函数**，逐输入与非 trace 结果精确一致，trace 不进入计时。

## 官方参照与共同精度

使用 [官方 qpOASES](https://github.com/coin-or/qpOASES) `releases/3.2.1`，源码提交 `51d3fbea30142d3acbf40cf7a1c519efc27ea67b`。该标签的 CMake 版本字符串仍写 3.2.0，未据此改称另一版本。使用 [`SQProblem::hotstart(H_new,...)`](https://github.com/coin-or/qpOASES/blob/51d3fbea30142d3acbf40cf7a1c519efc27ea67b/include/qpOASES/SQProblem.hpp) 的变矩阵重载，非固定 H 接口。H 为浅引用，桥接层双缓冲保留旧 H 到更新完成；所有节点/问题仍是相同 6/7 维箱 QP，不改变原主方法。

官方默认双精度选项，仅关闭输出；nWSR=1000，不重试。隔离编译，GCC 9.5.0、Release `-O3 -finline-functions`、PIC，C++11 桥接；官方 BLAS/LAPACK replacement 路径。环境无升级，主算法仍为 NumPy。CPU 为原 i7-13700K、逻辑 CPU4、OMP/OpenBLAS/MKL 单线程。完整版本、编译标志、库哈希和资源在 `provenance.json`。

共同质量为箱违反 ≤1e-8、原始 projected KKT ≤1e-5、尺度归一化 projected KKT ≤1e-8、相对合格原活动集目标的尺度化差 ≤1e-8。原始返回和任何舍入投影后的方向分别复算。目标差小不替代 KKT；原生返回码不替代检查。

原 OSQP eps_abs=1e-8、eps_rel=0、polishing、20000 上限在 Panda 19/UR5e 2 个定向输入不合格（各五遍）。保留首轮全部记录后，**仅在离线参照**将上限增至 200000，其他设置不动，并对四内核做同一轮交错计时；不选取各方法两轮中的更快时间。UR5e 全部合格，Panda 仍有 3 个单边界输入达上限且未通过检查，完整保留，不继续搜参数。在线 OSQP 设置未改。

原活动集及 qpOASES 两库均全部合格；Clip 在定向库 Panda 1996/2000、UR5e 1898/1903 个 QP 不合格。它的低耗时不算同精度胜出。

### 效率来自哪里？

原自然库中 OSQP **内核**已比 NumPy 更快（约 14–15 对 24–27 µs），NumPy 的完整调用较短主要依赖更薄的接口；在某些多活动、病态局部 QP 上，缓存 OSQP 确有很高的迭代成本。但官方原生活动集在这些受限 QP 上仍然显著快于 NumPy，且全量合格。因此不能将“胜过当前 OSQP 接口”解释成“专用受限求解优于成熟同类”。本轮不切换主方法，不把微基准降幅外推为尚未运行的 qpOASES 整轨迹收益。

## 六条轨迹：相同输入的局部解释

每条取按时序最早 `||d_bound−d_clip||∞>1e-6` 的内部 QP，均为该帧第 0 次更新；六处 `previous_q` 精确相同。以下 joint 编号为 **1-based**；完整 JSON 使用 0-based。残差代价为真实 FK 的 `0.5||r_task||²`，两方向从同一线性化 q 使用 α=1，均满足原回溯的残差下降条件；某个 trial 未通过任务 verifier 时只是内部更新，不冒充返回的合法命令。

| 轨迹/帧（0-based） | 活动边界 | 其他关节重分配范数 | 更新前代价 | 有界 / Clip 更新后代价 | 已存后续结果 |

| Panda 050 /132 | J1物理 | 0.0432 | 4.21546 | 0.000128 / 0.059107 | 有界完成；Clip f133首次失败 |
| Panda 052 /106 | J2物理 | 0.2701 | 6.24851 | 0.000145 / 0.617867 | 有界完成；Clip f107首次失败 |

重分配范数针对无约束解原先未被直接截断的关节，使用归一化步长；其中特定关节可能在联合最优解中新激活另一边界（如 Panda 094 的 J3），不把它误称最终自由关节。所有 H/g/lo/hi、梯度/KKT、方向、八级真实非线性回溯和当前验收都已保存。

六条原记录的三遍完成/失败帧一致。前四条 Panda 及 UR5e 109 与边界后协同重分配的作用相符；UR5e 131 是明确反例：更低当前残差并不足以保证下一帧继续完成。局部对照是严格共同输入；分歧之后的两条闭环状态不再相同，不据不同状态下的百分比做单一因果证明。

4. **什么贡献有证据？** 有界联合求步相对同核裁剪的数值作用、两机器人有限工程折中及可检查的实现证据。活动集、约束 GN、阻尼/回溯/居中属于成熟组件；不支持新活动集原理、专用内核同类领先或普遍连续跟踪优势。
