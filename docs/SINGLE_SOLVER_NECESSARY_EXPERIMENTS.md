# 单一有界 GN：必要实验与贡献判断

## 结论

固定 κ=1 的实现仍有工程使用价值，但不是新的约束优化原理。有界联合求步相对裁剪的任务收益在 Panda 得到支持，在 UR5e 没有净完成增量；居中项未获净收益支持。专用 NumPy QP 内核比缓存 OSQP 更省时，是本轮较清楚的效率贡献，但限于当前 6/7 维问题和实现环境。

## 实际执行与证据口径

- 基线 `b34800d4e38f391ad873b0a95c152e7da4a1081f`；独立评估前的代码、精度及输入提交 `c5f729e5d31beee73dd2f06302e7a04d968d4579`。
- 两机器人各 160 个新 UID，四类各 40 条，每条 150 帧；七设置各三遍，共 6,720 次整轨迹运行、1,008,000 帧。48,000 个参考帧先通过原 verifier；核对 21 个历史身份文件，无 seed/UID/query hash 碰撞。旧 40/40 是开发观察。
- 主 GN/adapter 文件逐字节不变。原 0.01 初始阻尼、κ=1、30 次外层上限、50 次活动集上限、八级残差回溯、缩放及停止条件均保留。H 中为 λI 而非 λ²I；回溯仅检查任务残差，不宣称完整居中目标单调下降。
- Clip 和 OSQP 仅通过实例私有回调替换局部 QP；无全局函数替换、候选池或 fallback。OSQP 使用相同 H/g/lo/hi、固定完整上三角 CSC（保留零项）、A=I 和 update。轨迹开始将原生 x/y 初值归零，轨迹内 warm-start，不重新 setup。
- 原合同为 1 mm、0.5°、dt=20 ms、原 URDF 范围及速度容差。公共 verifier 不变；只接受才反馈，失败保持，目标继续推进。晚到但合法命令按原语义反馈，DTSR20 单列。
- Intel Core i7-13700K；共同逻辑 CPU 4，OMP/OpenBLAS/MKL 单线程，按完整轨迹交错，两个机器人顺序运行。TRAC 内部线程同样继承这一 CPU 亲和性，故结果是共同单核资源口径，不能外推到任意 CPU 资源分配。
- NumPy 2.4.4、SciPy 1.17.0、Pinocchio 3.9.0、OSQP 1.0.5、pin-pink 3.3.0；沿用原 NumPy 可选后端回退，不升级、不启用 Numba。公共 verifier 后端为 URDFKinematics，GN 几何为已核实的 Pinocchio。
- 所有方法相同三次非零合成热身，加 runner 一次静止热身。模型加载、热身和整轨迹 reset 在帧调用外；转换、动态边界、数值求解和最终验收均计入原外层调用。setup 单列，不拿重复 setup 制造 OSQP 劣势。
- 完整 UID 为统计单位，三遍先在 UID 内平均；固定 4,000 次 family 分层配对 bootstrap，描述性、未做多重校正的 95% 区间。保留全部失败与超时，不 winsorize、不补样本、不设总 gate。区间跨零/一不等于等效。
- q_ref 只证明参考路径可行及提供共同起点；在线不读未来或参考配置。参考路径可行不保证任意方法状态下一帧可行。失败不是数学不可行证明。

### 边界协同更新

Panda 相对同核 Clip 稳定恢复 4 条且无损失：trajectory_050、052（近奇异），094、096（关节边界返回）。完成差 +2.50 pp，95% 区间 [0.625,5.000] pp。UR5e 恢复 trajectory_109，却损失 trajectory_131，净完成增量为零，累计成本点估计增加 9.1%。这是机器人/负载相关的收益，不是超越所有约束 IK。

开发采集固定的 8 条/机器人中，Panda 1,149 个实际 QP 无活动边界；UR5e 1,160 个中仅 3 个激活单帧位移边界，均非物理限位（trajectory_30 的 124/136/137 帧）。非受限关节重分配范数为 0.1430、0.0753、0.0670（归一化步长）；裁剪目标差为 1.3334、0.3978、1.3867。这直接说明截断方向不等于求解箱约束 QP，但不估计普遍发生率。

### 居中项

Panda κ=1/κ=0 都完成 154 条，却各稳定获得和丢失 3 个 UID。UR5e κ=1 只稳定损失近奇异 trajectory_071，没有恢复。κ=1 的平均加速度 RMS 也更高：Panda 3.725 对 2.975、UR5e 4.943 对 4.811 rad/s²。不支持居中项作为独立核心增量；本轮不事后切换主方法或再选参数。

## 成熟求解器的实际折中

相对 TRAC 5 ms，主方法 TSR 点估计多 3.125/2.917 pp，但累计成本点估计多 1.1%/18.9%，P50/P95 更高而 P99 更低。Panda 的 TSR 区间跨零，不能称全面优势。相对当前 Pink 单步适配器，总成本少 66.0%/57.6%，完成数点估计更高；UR5e TSR 差为 10 pp [5.625,14.375]。这些结果依赖当前软件、负载和共同单核资源。

## 最后六个判断

1. **独立数据上仍有用吗？** 有：Panda 154/160、UR5e 158/160，但不是开发满分的复现或普遍保证。
2. **有界协同更新贡献什么？** Panda 稳定多完成 4 条；UR5e 一得一失。真实机制成立，任务增益有负载边界。
3. **居中项有增量吗？** 不支持净增量：Panda 三得三失，UR5e 只损失一条，κ=1 平均加速度 RMS 更高。
4. **专用内核有什么效率贡献？** 合格开发 QP 上少约 40–43% 完整子问题时间；同核整轨迹少约 32%/18%，共同成功子集约 8%。这是实现效率，不是新理论。
5. **相对 TRAC/Pink 值得吗？** 有条件值得，尤其相对当前 Pink；相比快速 TRAC 须接受更高常规帧和共同成功轨迹成本，不是全面替代。
6. **什么创新得到支持？** 约束 GN/QP、活动集、阻尼、回溯和居中均属成熟成分。本轮支持有效实现、受控数值机制及有限条件下的工程收益，尚不足以主张新的约束 IK 原理或普遍优越算法。本轮到此停止，不追加模块或改论文。
