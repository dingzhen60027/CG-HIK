仓库 `dingzhen60027/CG-HIK`；分支 `codex/hierarchical-v5`。
起点 `8e754127bb56ec6054ef197f7f1b4e2324611b91`。

## 目的

先把已有真实失败中的合法当前命令找出来，而不是继续为假想下一目标优化评分。
本任务是建立有效的最小数值参照和可执行恢复能力，不预先声称是新论文算法。
不另起研究分支，不修改任务、URDF、原verifier或旧结果，不继续嵌套TAR/Elastic。

## 必须直接执行的工作

1. 阅读本包README，取 `repeated_results.json` 的四个成功关节向量。
   在原项目、每个输入自己的previous_q、target和dt下调用原verifier。
   不运行IK即可先确认它们是否构成项目内的合法命令。保留第五个未解决输入。
   如果不同，查明本地公开链与原链差异，不能直接宣称已恢复。

2. 把 `probe.py` 中的**标准有界TRF参考**接到原项目运动学和解析Jacobian。
   不重新起算法名，不把调用SciPy包装成新数值算法。
   仅优化当前q；用关节速度步长归一化变量、用真实位置/姿态容差归一化残差；
   可用范围始终为URDF bounds与真实previous_q单帧可达区间的交集。
   找到通过原verifier的命令就停止；不读未来目标、不生成场景。
   最多50次函数评价，外层20ms为实际评价时限，完整记录超时；
   在迭代回调中检查剩余时间，不声称可以精确中断native内部调用。
   minimax同样恢复4个且更慢，本轮不把它升级成新主方法。

3. 在最新开发比较的全部唯一首次失败输入上测试该参照，先输出：
   当前输入是否合法恢复、真实残差、步长、耗时以及原失败来源。
   失败输入是被选中的困难集合，恢复比例不代表一般成功率。
   对每个源方法自己的状态测试，不能用另一方法的状态替换。

4. 同一任务中继续运行原有全部40条开发轨迹/机器人，从第0帧开始。
   只比较：
   - 原task-aligned TRAC-IK 5ms；
   - 当前固定Pink；
   - 当前帧有界TRF单独运行；
   - TRAC-IK 5ms失败后，在剩余周期内执行一次同一当前帧TRF。
   最后一项只有两个数值步骤，是实用组合基线，不宣称其串联本身创新。
   正常成功帧直接返回，不再运行TAR或13个后续节点。
   不改变目标索引，不放慢轨迹，不放宽合同，不重置到reference。
   所有首次失败以后的帧仍计入总成本和完成表现。

## 科研边界

本轮不写“全新算法”，不承诺论文已成立；不从局部恢复推断完整续接恢复。
有界TRF之前已经作为仓库求解工具出现，先列清与原TRF的变量尺度、目标尺度、
动态关节界、导数、停止条件差异；实现完善不能直接作为方法创新。

与成熟工具等价的恢复先归为基础能力。若后续要提出算法贡献，必须对着本参照仍然
遗漏的约束情形证明新结构的增量，不能再以低效或错误配置的基线制造优势。
本轮不再设计新的未来余量、惩罚、网络或任务。不自动修改论文。
