## 0. 本轮交付与边界

本轮交付一套可从第0帧运行的在线算法，以及统一的开发比较；不是再交一份只解释负结果的报告。不重建平台、不换机械臂任务、不增加Git分支，不在Elastic/Minimal/CR-IK类之间继续套壳。旧论文与冻结结果原样保留。

只做一个方法：直接把当前命令和多个可能下一目标的修正配置放进同一个稀疏优化问题。工作名Task-Admissible Recourse IK（TAR-IK），名称仅作实现区分，不代表已建立新颖性。

执行顺序为：数学检查 → 单一在线实现 → 小样本集成 → 完整开发比较。不要在每一步结束后再生成下一份计划等待指令；完成本任务规定范围后提交结果。

## 1. 问题与motivation

现有CR-IK构造指定右逆B并计算min_i(slack_i/||B_i||)。它是一个固定补偿策略的局部下界，不是全部任务可接受修正的能力。此前反例已经说明两处损失：
1. 为抵消目标变化而保持名义残差，未充分利用可接受的残差方向与大小；
2. 预先固定关节补偿分配，不能根据逐关节剩余空间自由改变分配。
这些反例证明的是代理目标可能排序错误，不证明它已解释全部机器人失败。

唯一研究问题：
在同一当前任务合同下，能否直接优化一个共享的当前关节命令，使若干可能的下一目标分别存在低违约的合法关节修正，而不依赖指定右逆的半径评分？

不用“首次考虑容差/首次鲁棒IK/首次预测IK”描述贡献。要检验的增量是任务容差内的自由修正相对固定补偿与名义预测的任务收益和计算代价。

首先阅读：
- docs/CRIK_ELASTIC_LOCKED_EVALUATION.md
- src/confik/correction_reserve/geometry.py
- 当前TRAC、Pink适配器、verifier与原轨迹生成器

## 2. 唯一数学问题

输入：真实上一接受关节状态q_prev、当前目标x_t、上一目标x_(t-1)、dt。
沿用原目标外推，仅使用当前及历史信息，不读取真实下一目标、未来参考q或成功witness作为在线seed。

公共合同沿用仓库原值：位置1 mm、姿态0.5度、dt=20 ms、原URDF范围、逐关节速度和数值容差。b_i=qdot_max_i*dt+velocity_tolerance，S=diag(b)。不放宽公共verifier。

第一版使用固定的有限下一目标集合，不再拟合或调节历史需求r_t：
W={0,+e1,-e1,...,+e6,-e6}，共13个节点。
e_j为六维归一化坐标轴；位置乘epsilon_p，旋转扰动用Exp(epsilon_R*w_R)左乘预测姿态。所有方向在同一世界坐标系下定义。
这些顶点对应归一化L1单位球，不是L2单位球或六维立方体；它不是95%概率集合。真实预测误差是否落在其中必须记录。

决策变量：
- 一个共享当前配置q；
- 每个w_j对应的下一配置z_j；
- 一个非负的最坏未来位姿超差量tau。

定义g(z,x)=max(||p(z)-p_x||/epsilon_p, angle(R(z),R_x)/epsilon_R)。

求解：
min 0.5*||S^-1(q-q_anchor)||^2 + 0.5*tau^2

约束：
- q满足当前位姿合同、原关节范围及从q_prev出发的单帧步长约束；
- 对每个j，z_j满足原关节范围，且|z_j-q|<=b；
- 对每个j，位置归一化误差<=1+tau，姿态归一化误差<=1+tau；
- tau>=0。

q_anchor来自一次task-aligned TRAC-IK 5ms调用；若其未返回合法命令，则用实际q_prev作数值初值。不得借用reference q。

关键语义：
- 所有场景共享同一个q，禁止每个场景分别选择当前q后再挑赢家。
- z_j可分别变化，禁止强制z_j=z0+B*w_j；固定B只放在机制对照。
- tau是直接由未来目标实际位姿误差计算的超差，不是旧gamma/xi换名字。
- tau>0的未来z_j不一定通过原位姿合同，不得标成合法witness或部署命令。
- 当前q的合同从不松弛。只有当前q执行，未来节点只作规划变量。
- 实际tau=0且各节点逐一通过原verifier时，才能称这13个节点有已验证的一步修正。

这是一个联合程序，13个z_j并列存在。不是逐场景串行调用13次完整IK，更不是外层评分内层套13个求解器。

## 3. 数值实现：一套独立内核

复用已安装的Pinocchio、Clarabel、URDF/残差定义及公共verifier。
采用单阶段序列凸化，每帧最多2次线性化更新，不加primary/secondary双优化。

每次更新：
- 当前q在当前迭代点线性化；
- 后续场景采用同一个名义参考点与共同的位姿残差Jacobian；
- 将目标扰动以一致的SO(3)目标侧导数写入同一仿射模型；
- 用二阶锥表达位置/姿态范数约束，以线性约束表达关节/速度/信赖域；
- 所有场景一起调用一次Clarabel，使用固定稀疏模式与数据更新；
- 原固定右逆不再用于主目标或能力判定，可仅用于初始化和对照。

保留当前0.5个归一化关节步长的信赖域初值及已有短回溯，不通过无穷次子迭代凑成功。秩不足不能自动判定任务失败；直接约束形式应允许容差吸收无法精确补偿的分量。

真实FK复算当前q、所有z_j的误差和tau，再比较真实目标值。不能只因线性目标改善就采用。
初始q_anchor合法时，用z_j=q_anchor构造一个有限超差的可行初始参照；后续候选必须当前合法、未来关节/步长合法且实际目标改善。不得另开一层优化专门给参照评分。
有更好的初始化可以复用但必须不读取未来，计时包括初始化。

原命令已经具有零超差后续修正时，零改动目标为0，没有理由再改命令。不要给z_j额外添加正则项后仍声称这个性质原样成立；数值稳定问题应先通过变量尺度解决。

如果线性化未找到可采用结果，返回本帧已有合法TRAC命令；没有合法当前命令则如实失败。失败回退只允许这一层，不串接CRIK/Minimal/Elastic/Pink等多级solver。备用和所有优化均计入总时间。

不升级环境、不新加预测网络、不增加时域、不增加候选池、不扫新的惩罚权重。第一版目标系数固定为1。

## 4. 数学检查必须先通过，但不单独占一轮开发

运行任务包test_linear_recourse.py，并在真实SOCP内复现相同结论：
1. 容差反例：r=1，候选A的最小超差0.3，B为0。
2. 冗余分配反例：r=2，A最小超差0，B为0.2。
3. 秩亏但误差仍被任务容差容纳时，不能直接判失败。
4. 共享当前命令的反例：正确共享q最小超差0.4；错误给每个场景独立q会伪装成0。
5. 对共同仿射模型，在顶点合法时，凸组合的修正仍在凸关节/位姿集合内。

第5项是标准凸性结论，不能宣称是新的鲁棒控制定理。真实非线性FK不继承该保证；不同场景使用不同仿射展开时也不能直接援用该证明。
这些检查只证明数值对象与定义一致，不是机器人性能结果。

## 5. 只保留必要对照

完整开发主表：
1. task-aligned TRAC-IK 5ms；
2. task-aligned TRAC-IK 20ms；
3. 已有固定版本Pink；
4. 同核名义预测：W只含0，其他目标、约束、数值预算相同；
5. 同核固定补偿：相同13目标与位姿容差，将z_j限制为z0+B*w_j；
6. 新方法：13目标、各z_j自由求解，共享q。

固定补偿B使用同一名义点的尺度一致伪逆映射，每次共同线性化固定。秩亏时使用最小二乘映射，按真实残差评价，不能故意让对照直接退出。它不是原CR-IK的完整复现，必须正确命名。

不将未适配好的RangedIK零完成作为优越性证据。RangedIK必须进入文献差异说明；性能表由当前可用强基线支撑。不重跑旧mu网格或全部历史版本。

两个主要消融分别回答：多种目标变化是否必要；自由关节修正是否比指定右逆分配有用。新方法仅胜过旧CR-IK，不足以形成主要贡献。

## 6. 执行与评价：直接交付机器人结果

先复用原开发数据，每台40条、每条150帧。小样本集成只用每类固定前两条，不按算法成败选样本；数值正确后继续完成全部开发轨迹。
允许修正导数、尺度、计时或稀疏实现错误，不允许遇到不利结果就新增模式、罚项或更换研究问题。旧已观察测试不能重新命名为独立新测试。

所有方法第0帧开始，接受才更新自身previous_q；失败保持，目标继续推进。不同方法未来状态可以不同，不用reference替换。

主指标：TSR、DTSR20。
辅助：外层P50/P95/P99、累计时间、位姿误差、关节步长利用率、加速度RMS、恢复/损失UID、优化调用率、回退率。
新增机制指标仅限：预测超差、真实场景超差、实际未来目标落入W的比例，以及同输入下真实非线性下一步修正成功。

机制比较：每条开发轨迹预先取一个固定帧，所有方法接收同一个previous_q和当前/历史目标；使用相同后续数值参照评估返回的q。测试方向必须同时包含优化顶点和未参与优化的混合方向；L1集合内部与外部结果分开。不得只在优化过的12个轴向上评价。
任何后续命令都须从该方法实际返回的q出发验收。参照未找到解不是数学不可行。未来场景超差、局部模型与真实结果分开记。

计算目标是正常帧数毫秒、P95争取<5ms、按时成功不劣于成熟基线的有意义折中；这些是设计目标，不是保证，也不是必须所有行同时改善的总gate。若更慢，必须用明确任务收益说明成本，不以“总归小于20ms”证明优越。

单位为完整trajectory；TRAC三次搜索是轨迹内重复。保留全部类别、失败和超时。确定性基线重复计时不计作新增独立样本。
