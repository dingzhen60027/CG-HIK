# Official BoundMPC interface check — not a scan baseline result

The upstream source is TU-Wien-ACIN-CDS/BoundMPC commit
`b286df18641145bb97b31f29387227e4089a1ba4` (MIT, Thies Oelerich).
`official_example_check.json` contains three real headless updates using the
official experiment-1 IIWA path, initialization and weights. The source entry is
`src/confik/process_scan/boundmpc_check.py`. ROS2 Humble message types were built
with system Python 3.10; they were not replaced with stubs.

The actual backend was CasADi/Ipopt with bundled MUMPS, not MA57. Outer and
library-reported update times are both retained. These three calls are an
interface check, not a complete official experiment, a hardware run or an
evaluation of the paper's real-time implementation.

`gen_traj_opt_nlp_deps.cpp` is the code generated by that actual construction;
its header identifies CasADi's MIT-0 template terms. The upstream MIT notice is
included in `../provenance/third_party_licenses/BoundMPC_MIT.txt`.

The Panda/UR5e robot-state and coupled scanner-process mappings have not been
validated. All requested scan B3 slots therefore remain `not_evaluable`, with
null performance values. The official example's elapsed times are not inserted
into the scan comparison and are not evidence that BoundMPC is slow or fails
the scan task.
