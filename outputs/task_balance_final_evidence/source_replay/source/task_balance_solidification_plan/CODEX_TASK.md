## 2. A：真实来源的目标流，不再造另一条合成扫描

### A1. 指定来源与数据量

当前报告未找到项目内可用的真实Cartesian日志。本轮指定一个公开来源：DROID官方Panda数据。

先读官方文档与控制源码，记录实际读取的版本：
- `https://github.com/droid-dataset/droid/blob/main/docs/the-droid-dataset.md`
- `https://github.com/droid-dataset/droid/blob/main/droid/franka/robot.py`
- `https://github.com/droid-dataset/droid/blob/main/droid/robot_env.py`
- 同版本的姿态变换及记录器代码。

官方文档提供100-episode调试子集`gs://gresearch/robotics/droid_100`及低维原始`trajectory.h5`。
首选依据官方100-episode子集的身份索引读取对应低维记录；能定向取raw HDF5就不下载视频。若需要RLDS小子集，最多下载该官方示例子集，不下载TB级完整集，不解码不需要的图像。

不要安装整个DROID硬件控制栈，不运行启动控制器、杀进程、机械臂回零或运动命令。只读取公开数据与源码。

固定一个episode-ID哈希排序，选30个字段与时间语义可用的完整episode：6个只用于接口核对，24个用于锁定评估。选择不得依赖IK成败、minimax是否激活、关节是否接近边界。尽可能使接口核对与评估来自不同记录session；无法分离时如实记录，并按session聚类。

所有合格/排除理由、候选清单和选定ID在运行被测方法前保存。不因没有恢复事件扩大样本或换数据源。该子集不是DROID总体的概率样本，不能外推现场发生率。

若授权、下载或必要字段不可获得，记录实际阻塞与尝试，继续完成B和写作准备；不伪造日志、不以合成扫描替换，也不自动转向另一个大数据集。本轮不会因此反复增加任务。

### A2. 正确的输入，比再多几千帧更重要

读取真实的“所请求目标”，不是把下一帧观测FK当目标：
- 目标优先为文档确认的`action_dict/cartesian_position`或raw中对应字段；
- 当前关节状态优先为该action生成时记录的robot_state，若只有observation必须核对其配对时序；
- `action_dict/joint_position`只用于离线验证是否已有合格见证，不得作为种子或输入提示；
- observation的Cartesian pose是状态，不可代替所请求目标。

字段路径必须由实际文件和记录器确认，不把RLDS文档的路径硬套到raw HDF5。

核对姿态表示、Euler顺序、单位、基座坐标系、工具坐标系、关节顺序、观测与命令的时间对齐。官方源码使用的Cartesian姿态并非可直接当旋转向量；必须复用或严格等价实现其变换。

仅根据官方URDF/已知固定变换处理工具与基座差异。不允许用IK胜负挑选变换，不允许在评估目标上拟合校准后称独立验证。用6个接口episode检查本项目FK与源状态位姿的偏差，保存阈值、残差分布及来源依据；明显的模型/时间不一致未解决时，不运行会混淆误差来源的主比较。

时间间隔必须保持来源语义：官方平台当前代码为15Hz，实际版本/记录可能不同，以核实的记录与控制配置为准。主回放不把一个约66.7ms命令改成20ms位移额度；也不能把日志丢帧造成的大时间差直接当作控制器允许更大位移的理由。缺乏时间戳时，使用经过版本核实的固定控制周期并标注“配置重建”。丢帧/非单调时间记录单列。

主方法的计算评价期限仍报告20ms，这与输入的运动周期是两个不同量。
位置1mm、姿态0.5°用于本研究的软件验收，不称DROID原任务公差，不称实机位置准确度要求。

### A3. 只做共同输入的离线回放

对每条记录的实际当前状态q_log(t)，各方法接收相同target(t)、q_log(t)和来源控制周期。每个查询都用记录状态，不用各方法输出改变后续真实数据。

只比较五个现有设置：
1. 当前相对进展主方法；
2. 同κ原GN；
3. 同核fixed_qp2；
4. 同外层Clarabel；
5. 现有直接同合同SQP。

三遍交错、同CPU与线程设置，完整外层计时。冻结当前配置，不在这些记录上调求解参数。

只在Panda上使用该来源，不把Panda关节序列强行映射到UR5e。原来两机器人结果保留。此项叫“真实机器人来源的离线IK回放”，不叫实机闭环试验或任务成功率实验。

### A4. 首先报告问题出现得多不多，再报告哪种算法更好

每episode及全体报告：
- 当前目标相对记录状态的两块归一化误差、关节边界余量与记录命令的实际位移利用率；
- 首步合法返回比例、需要额外对偶QP的比例、采用relative停止的比例，分母明确；
- 合格命令率、20ms内合格率、平均/P50/P95/P99时间；

所有记录查询都报告。若源commanded joint配置能通过本研究verifier，单列“独立见证确认可行”子集；未通过不代表请求不可行，求解失败不直接称漏解。不要因为缺少witness删除样本。

原始完整episode是统计单位，重复是其内部重复；多episode共享session时做session聚类/分组结果。不把帧数当独立样本数。不把全部通过产生的退化bootstrap零宽区间解释为等效。

若几乎从不触发额外平衡或没有命令恢复，直接给出这个结果：在该数据来源及验收设定中不是主要瓶颈。不能缩短dt、放大动作、注入噪声、丢弃普通片段来制造有利现象。

### B2. 任务容差变化时保持几何配对关系

不能简单收紧旧目标后仍称全部有可行witness。

对位置/姿态容差两项变化，以原q_w及原目标偏移方向构造相同归一化偏移alpha的新目标：

p_new = FK_p(q_w) + (eps_p_new/eps_p_old)*(p_old-FK_p(q_w))

R_new = Exp((eps_R_new/eps_R_old)*Log(R_old*R_w^T))*R_w

使用实际项目一致的SO(3)表示，逐查询用该配置的verifier核验原q_w仍合法。
q_previous与关节条件保持不变。每个新目标保存parent_query_uid，并如实标为“同anchor、不同任务要求的配对重构”，不是相同绝对目标上的直接性能差。

nominal的三个η配置使用完全相同的原始目标。

### B3. 对照与数量

nominal：三个η主方法实例＋原GN＋现有SQP，共五个设置。
两个收紧容差条件：各运行η=.25＋原GN＋现有SQP，共三设置/条件。

每机器人270查询、三遍；两机器人总计约17,820次调用（不含必要的warmup与日志读取）。不再跑全部历史基线。

原GN、SQP也必须使用对应的共同验收条件、相同目标及一致归一化；SQP数值内部裕量沿用原归一化定义，不重调。

报告全部配置的合格命令覆盖、成本、局部QP次数、贴边比例、获益/损失。区分“调η的数值敏感性”与“改变任务要求的适用性”，不把任务尺度变化当solver参数优化。
